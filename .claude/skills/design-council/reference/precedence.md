# Design Council -- Conflict Avoidance

`design-council` rosters two authorities that own disjoint concerns --
`impeccable` for everything visual, the Emil trio (`emil-design-eng` /
`find-animation-opportunities` / `animate`) for everything motion. That split
makes most collisions structurally impossible: a spacing recommendation and a
duration recommendation are never the same finding. What remains is a short
ladder, not a merge process.

## Ladder

Apply in order. First match wins.

1. **The brief wins.** An explicit user requirement beats any skill's
   default. (`impeccable`'s own rule, promoted to council law.)
2. **The accessibility floor is never overridden** by any polish or motion
   preference.
3. **Preserve the existing design absent a named defect.** The current
   implementation is evidence of intent, not something to improve on by
   taste. A change needs a concrete usability, accessibility, consistency, or
   quality problem behind it.
4. **Domain authority:**
   - Motion, easing, duration, interruption --> `emil-design-eng`
   - Everything visual (typography, spacing, layout, color, component
     consistency, a11y, responsive) --> `impeccable`
5. **Genuine ties go to the user**, never to a blended compromise.
